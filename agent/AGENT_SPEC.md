# אפיון סוכן "Dropshipping Operator"

סוכן חצי-אוטונומי שמריץ את עבודת השיווק, התוכן, התפעול והמכירה של עסק דרופשיפינג אחד, עם שערי אישור אנושיים על כל פעולה שמשפיעה על כסף, חשבונות או לקוחות. הפרומפט המלא לסוכן נמצא ב-`agent/OPERATOR_PROMPT.md`.

## 1. דעה מקצועית ישירה: מה אפשר ומה אי אפשר לאוטומט

**אפשר לאוטומט כ-70-80% מהעבודה** (מחקר, תסריטים, ניסוח, ניתוח מספרים, דוחות, טיוטות תשובות ללקוחות). **אי אפשר ולא כדאי** לאוטומט מלא:

| תחום | למה לא אוטונומי מלא |
|---|---|
| פתיחת חשבונות (חנות, סליקה, פרסום, רשתות), KYC, מס | פעולות אנושיות לפי תנאי הפלטפורמות והחוק; ניסיון לעקוף = חסימה. |
| הוצאת כסף ופרסום ממומן | סוכן בלי עצירה אנושית יכול לשרוף את כל התקציב או להפעיל חשבון מודעות חדש שייחסם. בתקציב קטן אין מובהקות סטטיסטית, ולכן צריך שיקול דעת. |
| פרסום אורגני בנפח | פלטפורמות מדרגות נמוך תוכן לא מקורי, ו-TikTok דורשת תיוג AI. סרטון ויראלי נוצר מהבנה אנושית של הוק ושל מוצר, לא מכמות. |
| שירות לקוחות והחזרים | תגובה גרועה גורמת ל-chargeback, וספי ה-chargeback הוקשחו ב-2026. אנושי מאשר, הסוכן מכין. |
| אמון בחנות חדשה | דורש משלוח אמיתי, דוגמה שנבדקה וזמני אספקה כנים. |

המסקנה: הסוכן הוא "מנהל תפעול" שמכין הכול ומבקש אישור. אפשר להרחיב אוטונומיה בהדרגה, ורק אחרי שהוכחה יציבות (תקרות הוצאה, אפס אזהרות פלטפורמה).

## 2. ארכיטקטורה (Claude Code: סקילים + שגרות)

הבחירה שלך: **Claude Code עם סקילים ושגרות מתוזמנות**, ללא עלות תשתית נוספת.

```
agent/
  OPERATOR_PROMPT.md        # הפרומפט הראשי (מוצמד ל-CLAUDE.md / שגרה)
  AGENT_SPEC.md             # המסמך הזה
  state/                    # זיכרון ומקור אמת
    products.json           # סל המוצרים הפעיל
    criteria.md             # קריטריוני בחירה ושערים
    experiments.md          # יומן ניסויים
    metrics.csv             # מדדים יומיים
    loss_ledger.csv         # פנקס הפסדים מול התקרה
    decisions.md            # יומן החלטות
    sources.md              # מאיפה נמשכים נתונים
  queue/                    # תוכן שממתין לאישור
.claude/skills/             # (נבנה בסשן הבא)
  product-scout/  content-studio/  store-ops/
  analyst/  support-drafter/  compliance-guard/  ads-manager(locked)/
```

**תפקידים (סקיל/סאב-אייג'נט לכל אחד):** Product Scout, Content Studio, Store Ops, Analyst, Support Drafter, Compliance Guard (חוסם לפני כל הצגה), Ads Manager (נעול עד שלב 2).

**שגרות מתוזמנות (Routines):** יומית (איסוף מספרים, אנומליות, אצוות תוכן, הודעה אחת בעברית), שבועית (סקור-קארד, המשך/שיפור/הפסקה), חודשית (שערי שלב, אימות מחדש של נתונים לא מאומתים).

## 3. מודל אוטונומיה בשלוש רמות

| רמה | דוגמאות | מי מחליט |
|---|---|---|
| 0 אוטונומי | מחקר, חישובי break-even, טיוטות, דוחות | הסוכן, עם רישום |
| 1 הכנה + אישור | פרסום תוכן, שינוי מחירים/עמוד, הודעה ללקוח, החזר | אתה: APPROVE / REJECT / EDIT |
| 2 אנושי בלבד | חשבונות, KYC, תשלום, תקציב, חוזים, מס | אתה בלבד |

איסורים מוחלטים (ללא קשר לרמה): ביקורות מזויפות, מחסור מזויף, טענות רפואיות, העתקת מותגים, חשבונות נוספים לעקיפת חסימה, אוטומציית ספאם ועוד (מפורט בפרומפט, סעיף 5).

## 4. שלבי העבודה והשערים

`0-VALIDATE` (אורגני, ללא חנות) ← `1-TRIAL-STORE` (חנות עם תקרת הפסד) ← `2-PAID-TEST` (רק אחרי ארבעה שערים) ← `3-SCALE`. התנאים המספריים המדויקים נמצאים בפרומפט (סעיף 6). חוק הברזל: **אם אחד מארבעת השערים חסר, פרסום ממומן נעול.**

## 5. חיבורים נדרשים ואילוצי סביבה

| מקור/פעולה | דרך | הערה |
|---|---|---|
| חנות Shopify (הזמנות, מוצרים) | Admin API עם custom app token, קריאה בלבד בהתחלה | הטוקן ניתן על ידך כסוד סביבה, לא בצ'אט או בקבצים |
| אימייל תמיכה | מחבר Gmail (טיוטות בלבד, ללא שליחה אוטומטית) | שליחה = רמה 1 |
| גיליונות/מסמכים | מחבר Google Drive | לדוחות ולסל מוצרים |
| יומן | מחבר Google Calendar | תזכורות לשערים |
| אנליטיקה | GA4/Shopify Analytics בייצוא CSV בהתחלה | MCP ייעודי רק בשלב ממומן |
| פרסום ברשתות | הסוכן מכין, **אתה מעלה** (או כלי תזמון שאושר) | אין אוטומציית פרסום ב-API עד שיוכח שהיא בטוחה |

**אילוץ בסביבת הענן הנוכחית:** בסשנים הקודמים הפרוקסי חסם את WebFetch לרוב האתרים (Amazon, CJ, Shopify, TikTok), והחיפוש הוא חיפוש בלבד. לכן מחקר מוצרים בענן נשען על תקצירי חיפוש, ומחירי ספק הם הערכות עד שמישהו פותח את הקטלוגים בפועל. לפני הרצה קבועה יש להריץ את הסוכן בסביבה עם גישה לדפים (מחשב מקומי או סביבה עם רשת פתוחה).

**תוספים:** התוסף Marketing של Anthropic שימושי כבר בשלב 0 (תסריטים, תוכן, רצף אימיילים); תוספי פרסום (Windsor.ai, AdWhispr, Hyper Marketing, Trackian, Arcads) רלוונטיים רק בשלב 2 ודורשים חשבונות פרסום מחוברים.

## 6. מדדי הצלחה ובקרות סיכון

- תקרת הפסד כוללת ברירת מחדל $150, ללא פרסום ממומן עד השערים; מוצגת בכל הודעה יומית.
- הקפאה אוטומטית והתראה: disputes ≥ 1% מההזמנות, אזהרת פלטפורמה, או 80% מתקרת ההפסד.
- כל מספר בהמלצה מגיע עם מקור או תג `[ESTIMATE]` / `[UNVERIFIED]` / `[SYNTHESIS]`.
- הסוכן מחויב לומר "הפסק" כשהמספרים אומרים להפסיק.

## 7. מפת דרכים לבנייה (הסשן הבא)

1. יצירת `agent/state/*` ומילוי `products.json` מסל המוצרים.
2. כתיבת הסקילים: Product Scout, Content Studio, Compliance Guard ראשונים (Tier 0 בלבד).
3. שגרה יומית עם הודעה בעברית; חיבור Gmail בטיוטות.
4. Analyst + ייבוא CSV; Store Ops אחרי הקמת חנות.
5. Ads Manager רק אחרי ארבעת השערים.

## 8. מה נדרש ממך כדי להתחיל

פגישה עם רו"ח (עוסק פטור ואופן קבלת כספים מחו"ל), החלטה על תקרת הפסד, הזמנת דוגמה אחת, ופתיחת חשבון PayPal עסקי ובדיקת שער ישראלי. כל אלה פעולות רמה 2 שהסוכן לא יבצע במקומך אלא רק ילווה ויזכיר.
