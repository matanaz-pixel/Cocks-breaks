# תוכנית בדיקה ידנית על מכשיר אמיתי

מטרה: לוודא שהאפליקציה עובדת באמת על טלפון, כולל מה שבדיקות היחידה לא יכולות לבדוק: בידוד תהליכים, MediaStore, הרשאות, ביצועים וממשק.

**ציוד:** טלפון אנדרואיד (רצוי גם אחד עם אנדרואיד 13+ וגם אחד ישן יותר, API 26–29, אם יש), כבל USB, מחשב עם `adb`, ורצוי כרטיס SD.
**גרסה לבדיקה:** `app-debug.apk` (בדיקות 5 ו-6 דורשות debug).

> **אזהרה:** בצעו את הבדיקות על טלפון בדיקה או על תיקיית בדיקה ייעודית (`/sdcard/Pictures/GDTest/`), לא על התמונות היחידות של מישהו.

## 0. הכנה

```bash
adb install -r app-debug.apk
adb shell mkdir -p /sdcard/Pictures/GDTest
# תמונה תקינה אחת (מהמחשב) וסרטון תקין אחד
adb push good.jpg /sdcard/Pictures/GDTest/good.jpg
adb push good.mp4 /sdcard/Pictures/GDTest/good.mp4
```

כדי שקובץ חדש ייכנס לאינדקס: `adb shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file:///sdcard/Pictures/GDTest/<name>`.
אם לא נקלט, מפעילים מחדש את הטלפון או פותחים את תיקיית הבדיקה באפליקציית Files של המערכת.

## 2. קבצים פגומים (אחד אחד)

מכינים בתיקיית הבדיקה:

```bash
D=/sdcard/Pictures/GDTest
adb shell "head -c 100000 $D/good.jpg > $D/truncated.jpg"         # JPEG חתוך
adb shell "touch $D/zero.jpg"                                      # 0 בייטים
adb shell "cp $D/good.jpg $D/wrongext.png"                         # סיומת שגויה
adb shell "echo not-an-image > $D/text.jpg"                        # טקסט בשם JPG
adb shell "head -c 500000 $D/good.mp4 > $D/truncated.mp4"          # MP4 חתוך (בלי moov אם הוא בסוף)
```

מריצים סריקה מלאה. בדוח צריך להופיע:

| קובץ | תוצאה צפויה | סיבה |
|---|---|---|
| `truncated.jpg` | חשוד | "קובץ JPEG חתוך – חסר סוף קובץ" |
| `zero.jpg` | פגום | "הקובץ ריק (0 בייטים)" |
| `wrongext.png` | חשוד | "הסיומת לא תואמת לתוכן האמיתי" |
| `text.jpg` | פגום | "תוכן הקובץ לא תואם לפורמט שלו" |
| `truncated.mp4` | פגום או חשוד | "חסר moov" ו/או "הקובץ נחתך" |
| `good.jpg`, `good.mp4` | **לא** מופיעים בטבלאות | |

לכל שורה בטבלה: לוחצים **פתח**. הקובץ נפתח באפליקציית המערכת, או שהיא מציגה שגיאה, בלי שהאפליקציה שלנו קורסת.

## 4. אינדקס לא יציב

בזמן שהסריקה בשלב "בודקים כל תמונה וסרטון" (כדקה אחרי שהתחילה), יוצרים ומוחקים קבצים כל כמה שניות:

```bash
for i in $(seq 1 40); do cp $D/good.jpg $D/churn_$i.jpg; am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file://$D/churn_$i.jpg >/dev/null; sleep 1; done
```

**צפוי:** בדוח מופיעה הסיבה "אינדקס המדיה לא יציב" עם מספרי שינויים.
בסריקה שקטה, בלי לגעת בטלפון, **צפוי** 0 שינויים או מעט מאוד.

## 5. בידוד קריסות (המבחן החשוב ביותר, גרסת debug)

```bash
D=/sdcard/Pictures/GDTest
adb shell cp $D/good.jpg $D/GD_TEST_CRASH_1.jpg
adb shell cp $D/good.jpg $D/GD_TEST_HANG_1.jpg
# לעדכן את האינדקס (broadcast או הפעלה מחדש)
```

| # | צעד | תוצאה צפויה |
|---|---|---|
| 5.1 | מריצים סריקה מלאה | **הממשק לא קורס ולא נתקע** (גם כשתהליך הבדיקה מת). מוצג "נמצאו N קבצים שגרמו לקריסה", ו"תהליך הבדיקה אותחל מחדש N פעמים" |
| 5.2 | פותחים את הדוח | `GD_TEST_CRASH_1.jpg` ו-`GD_TEST_HANG_1.jpg` בטבלה "קבצים שקרסו או נתקעו". הסיבה הראשונה בדירוג: "קבצים שגורמים למפענח לקרוס", ברמת ביטחון גבוהה, והרמזור אדום |
| 5.3 | בודקים את הסיבות בטבלה | `CRASH` – "הפענוח קרס את תהליך הבדיקה", `HANG` – "לא הסתיים בזמן" |
| 5.4 | משווים זמנים | קובץ ה-HANG מוסיף כ-25 שניות לסריקה (5 שניות + ניסיון שני עם 20 שניות). שאר הקבצים נסרקים כרגיל |
| 5.5 | בודקים ש-`good.mp4` ושאר הקבצים התקינים **לא** סומנו כפגומים בגלל הקריסות | אין השפעה על קבצים אחרים |

**הרג תהליך באמצע (סימולציה של קריסה נייטיבית):**

```bash
adb shell ps -A | grep scanner        # מוצאים את ה-PID של il.gallerydoctor:scanner
adb shell kill -9 <PID>               # תוך כדי סריקה
```

**צפוי:** הסריקה ממשיכה, מונה האתחולים עולה, והקובץ שנבדק באותו רגע נבדק שוב. אם הוא עבר בניסיון השני הוא מסומן "חשוד: תהליך הבדיקה קרס פעם אחת על הקובץ", ולא CRASHER.

**הפסקה כוחנית ומעבר להמשך:**

1. באמצע סריקה: `adb shell am force-stop il.gallerydoctor`.
2. פותחים את האפליקציה: מוצג "המשך את הסריקה שהופסקה". לוחצים.
3. **צפוי:** הסריקה ממשיכה מהנקודה שנעצרה (לא מתחילה מחדש), והקובץ שנבדק בזמן ההפסקה נבדק שוב.

## 7. עומס וביצועים (10,000 קבצים)

יוצרים 10,000 קבצים מעורבים:

```bash
adb push good.jpg /sdcard/good.jpg
adb shell 'mkdir -p /sdcard/DCIM/GDLoad; for i in $(seq 1 10000); do cp /sdcard/good.jpg /sdcard/DCIM/GDLoad/L_$i.jpg; done'
# אפשר להוסיף גם 500 עותקים של good.mp4
```

(כל הקבצים זהים, ולכן נוצרות גם קבוצות כפילויות: זה בדיקה לחיפוש הכפילויות.)
מריצים סריקה מלאה, ובזמן הסריקה, בטרמינל נוסף:

```bash
while true; do adb shell dumpsys meminfo il.gallerydoctor | grep -E "TOTAL PSS|TOTAL:"; sleep 20; done
adb shell dumpsys thermalservice | grep -i "status"
```

| קריטריון | עובר אם |
|---|---|
| אין ANR | הממשק מגיב לכל מגע במהלך הסריקה, ואין "האפליקציה לא מגיבה" |
| זיכרון יציב | ה-PSS של התהליך הראשי **לא גדל ללא הגבלה** (נשאר בטווח של כמה עשרות MB, לא עולה בקו ישר), וכך גם של תהליכי `:scanner` |
| אין OOM | אין `OutOfMemoryError` ב-`adb logcat -b crash` |
| חום | הטלפון אינו הופך לחם מאוד. אם הסטטוס התרמי מגיע ל-SEVERE, מוצגת הודעה והסריקה מושהית ואז ממשיכה |
| התקדמות | מוצג אחוז וזמן משוער שמתכנס, ו-ETA הגיוני |
| כפילויות | הדוח מציג קבוצות כפילויות וכמות מקום לפינוי, והסריקה לא נתקעת בשלב זה |

מנקים אחרי הבדיקה: `adb shell rm -rf /sdcard/DCIM/GDLoad /sdcard/good.jpg`.

## 9. בדיקות פרטיות והרשאות (מחשב)

```bash
aapt dump permissions app-debug.apk       # או: apkanalyzer manifest permissions app-debug.apk
```

**צפוי:** `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, `READ_EXTERNAL_STORAGE` (עד API 32), `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `POST_NOTIFICATIONS`, `QUERY_ALL_PACKAGES`, ו-`READ_LOGS` (מוצהרת אבל **לא ניתנת** עד שמריצים `adb shell pm grant`).
**אסור:** `INTERNET`, `MANAGE_EXTERNAL_STORAGE`, כל הרשאת כתיבה.

אפשר גם לוודא בזמן סריקה שאין תעבורת רשת: `adb shell dumpsys netstats | grep il.gallerydoctor`, או להפעיל מצב טיסה, והסריקה אמורה לעבוד כרגיל.

לפני ואחרי סריקה על תיקיית בדיקה, משווים את תוכן התיקייה (`adb shell ls -l --full-time`): אמורים להיות **אותם קבצים באותם גדלים ותאריכי שינוי**.
